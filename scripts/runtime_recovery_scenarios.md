# 설치 문제 상황 및 복구 제안

이 문서는 **완전 클린 Windows 환경** 또는 일부 런타임이 손상된 환경에서,
UTAU Auto OTO 실행 시 발생할 수 있는 대표 문제 상황과 복구 방법을 정리한 문서입니다.

특히 다음 목표를 염두에 둡니다.

- 사용자가 겪을 수 있는 문제를 **빠르게 분류**한다.
- 문제별로 **자동 복구 가능 여부**를 판단한다.
- UI에서 제공할 **원클릭 자동 진단/복구** 흐름의 기준 문서로 활용한다.
- 완전 자동이 어려운 경우에는 **수동 복구 안내**를 명확히 제공한다.

---

## 1. 기본 원칙

이 프로젝트의 Windows 런타임 복구는 **시스템 전역 Python/pip**보다 **앱이 관리하는 엔진별 환경**을 우선 기준으로 삼는다.
- MFA: `.env` + `setup_mfa.bat`
- 통합 복구: `runtime_recovery.ps1 -Target mfa`

따라서 사용자가 “Python이 없다”, “pip가 안 잡힌다”고 느끼는 경우도 실제로는 아래 중 하나일 가능성이 크다.

1. MFA 환경 자체가 아직 생성되지 않음
2. MFA 환경 안의 `python.exe`가 누락됨
3. MFA 환경 안의 `pip.exe` 또는 `pip/setuptools/wheel/pkg_resources`가 손상됨
4. 언어별 추가 의존성(한국어/일본어)이나 모델이 누락됨
5. 네트워크, TLS, VC++ 런타임, 보안 정책 같은 외부 조건 때문에 설치가 중단됨

---

## 2. 문제 상황별 예시와 복구 제안

### A. MFA 환경 생성이 중간에 실패한 경우

#### 증상 예시

- “MFA 실행 파일을 찾을 수 없습니다.”
- “MFA Python 런타임을 찾을 수 없습니다.”
- 설치 버튼을 눌렀는데 이후 단계가 전혀 진행되지 않음
- `.env` 폴더는 일부 생겼지만 `mfa.exe` 또는 `python.exe`가 없음

#### 가능한 원인

- micromamba 다운로드 실패
- micromamba 압축 해제 실패
- 백신 또는 보안 소프트웨어가 실행 파일 생성을 차단
- 설치 도중 사용자가 창을 종료함
- 디스크 용량 부족
- 경로 권한 문제

#### 자동 복구 가능성

**높음**

가장 먼저 시도해야 할 복구는 **환경 재설치**다. 기존 손상 상태를 부분 수리하기보다, 공용 MFA 환경을 처음부터 다시 구성하는 편이 성공률이 높다.

#### 권장 복구 순서

1. 현재 MFA 경로와 실행 파일 존재 여부 진단
2. `mfa.exe` 또는 `python.exe`가 없으면 **재설치 모드**로 전환
3. 내부 설치 루틴 실패 시 `setup_mfa.bat --non-interactive` 폴백 실행
4. 재설치 후 다시 진단하여 `ready` 상태 확인

#### UI 제안

- 버튼명: **자동 진단 및 복구**
- 사용자 메시지: “MFA 환경이 없거나 손상되어 다시 설치합니다.”
- 실패 시 안내:
  - 네트워크 연결 확인
  - 백신 예외 설정 확인
  - 디스크 여유 공간 확인

---

### B. `pip.exe`는 없지만 `python.exe`는 남아 있는 경우

#### 증상 예시

- “pip가 감지되지 않습니다.”
- `python.exe`는 있는데 패키지 설치가 실패함
- 일부 설치 단계에서 `python -m pip`는 되지만 `Scripts\pip.exe`는 없음

#### 가능한 원인

- 환경 생성 도중 packaging tool 설치가 누락됨
- pip 실행 파일만 삭제되거나 격리됨
- 일부 보안 프로그램이 `pip.exe`를 차단함

#### 자동 복구 가능성

**매우 높음**

이 경우는 환경 전체 재설치 없이도 `ensurepip` 및 `python -m pip` 기반 복구가 통하는 경우가 많다.

#### 권장 복구 순서

1. `python.exe` 존재 여부 확인
2. `import pip, pkg_resources, wheel` 검사
3. 실패 시 아래 순서로 자동 복구 시도
   - `python -m ensurepip --upgrade`
   - `python -m pip install --upgrade setuptools<81 wheel`
   - 가능하면 `pip.exe install --upgrade setuptools<81 wheel`
4. 복구 후 import 재검사

#### UI 제안

- 사용자에게 “Python 패키지 도구 복구 중” 상태를 명확히 표시
- 성공 시: “pip/setuptools/wheel 복구 완료”
- 실패 시: 환경 재설치 버튼으로 자연스럽게 이어지게 구성

---

### C. Python은 있지만 packaging stack이 깨진 경우

#### 증상 예시

- pip는 있는 것처럼 보이나 설치가 실패함
- `pkg_resources` import 실패
- `wheel` import 실패
- 언어별 의존성 설치 전에 기본 패키징 도구 점검에서 중단됨

#### 가능한 원인

- 부분 업데이트 중단
- setuptools/wheel 버전 충돌
- 이전 실패 설치의 잔여물
- conda/pip 혼합 상태로 인한 손상

#### 자동 복구 가능성

**높음**

이 경우는 기본 packaging stack 복구를 먼저 하고, 그 다음 언어 의존성 설치로 넘어가는 식으로 단계화하면 된다.

#### 권장 복구 순서

1. `python.exe` 확인
2. `import pip; import pkg_resources; import wheel` 검사
3. 실패 시 packaging stack 복구
4. 성공 후 언어별 패키지 점검으로 진행
5. 마지막에 모델 준비 여부 확인

#### UI 제안

- 진단 결과를 세부적으로 보여주기
  - Python 실행 파일: 있음/없음
  - pip 실행 파일: 있음/없음
  - packaging stack: 정상/손상
- “기본 Python 도구 복구 완료, 언어 패키지 점검으로 넘어갑니다.” 같은 단계별 메시지 제공

---

### D. 언어별 추가 의존성 또는 모델이 없는 경우

#### 증상 예시

- 한국어: 형태소 분석기 관련 import 실패
- 일본어: `spacy`, `sudachipy`, `sudachidict_core` import 실패
- MFA 모델 다운로드 실패
- 기본 MFA는 보이지만 실제 정렬 단계에서 언어별 오류가 발생함

#### 가능한 원인

- 언어 패키지 설치 누락
- 모델 다운로드 중 네트워크 실패
- 일부 패키지가 설치돼도 import가 실패하는 반쪽 상태
- Windows 환경 특성상 특정 한국어 형태소 분석 패키지가 직접 빌드되지 않음

#### 자동 복구 가능성

**높음 ~ 중간**

대부분 자동 복구 가능하지만, 패키지 저장소 접근 문제나 파일 손상 정도가 심하면 재설치가 더 빠를 수 있다.

#### 권장 복구 순서

1. 언어별 import 검사
2. 한국어/일본어 복구 루틴 실행
3. 모델 존재 여부 검사
4. 모델이 없으면 자동 다운로드
5. 그래도 실패하면 배치 폴백 또는 수동 복구 명령 제공

#### UI 제안

- 언어별로 분리된 안내 문구 제공
  - “한국어 지원 패키지 복구 중”
  - “일본어 토크나이저 의존성 설치 중”
  - “언어 모델 다운로드 중”
- 사용자가 “기본 환경은 살아 있는데 왜 안 되지?”라고 느끼지 않도록, **언어 패키지와 모델은 별도 단계**임을 안내

## 3. 추가로 자주 생길 수 있는 문제

### E. VC++ 런타임 누락

#### 증상 예시

- `msvcp140.dll` 관련 오류
- `vcruntime140.dll` 관련 오류
- “side-by-side configuration is incorrect” 메시지
- micromamba 또는 Python 실행 자체가 되지 않음

#### 자동 복구 가능성

**중간**

다운로드와 설치 시도는 자동화할 수 있지만, 운영체제 정책 또는 재부팅 요구 때문에 완전 자동 성공이 보장되지는 않는다.

#### 권장 복구 순서

1. VC++ 런타임 marker 파일 검사
2. 없으면 redistributable 다운로드 시도
3. silent 또는 passive 설치 시도
4. 재검사
5. 실패 시 공식 링크와 수동 설치 안내 제공

#### UI 제안

- “Microsoft VC++ 런타임 점검/복구 중” 상태 표시
- 실패 시 공식 다운로드 링크와 함께 “설치 후 앱을 다시 실행해 주세요” 안내

---

### F. TLS/인증서/프록시 문제로 다운로드 실패

#### 증상 예시

- micromamba 다운로드 실패
- HTTPS 연결 실패
- 인증서 또는 secure channel 관련 오류
- 동일한 버튼을 다시 눌러도 즉시 실패

#### 자동 복구 가능성

**낮음 ~ 중간**

앱이 재시도는 할 수 있지만, 회사 프록시/인증서 문제는 사용자의 네트워크 환경 변경 없이는 해결이 어려울 수 있다.

#### 권장 복구 순서

1. TLS 관련 오류 패턴 감지
2. PowerShell 다운로드 실패 시 curl 다운로드 재시도
3. 그래도 실패하면 네트워크 정책 문제로 분류
4. 수동 다운로드 링크 및 안내 제공

#### UI 제안

- “TLS/인증서 문제로 보입니다. 네트워크 정책을 확인해 주세요.” 같은 명시적 문구 제공
- 단순 “다운로드 실패”보다 훨씬 구체적인 원인 표시

---

### G. 백신/보안 제품이 파일 생성을 차단하는 경우

#### 증상 예시

- 다운로드는 됐지만 설치 파일이 사라짐
- `.exe` 또는 `.dll`만 선택적으로 누락됨
- 같은 단계에서 반복적으로 실패함
- 설치 로그는 성공처럼 보이지만 결과 파일이 없음

#### 자동 복구 가능성

**중간 이하**

앱이 재시도는 가능하지만, 보안 제품이 계속 파일을 격리하면 자동 복구만으로는 반복 실패할 가능성이 높다.

#### 권장 복구 순서

1. 결과 파일 존재 여부 재검사
2. 파일 생성 누락 시 보안 제품 간섭 가능성 경고
3. 예외 처리 안내 또는 임시 보호 해제 안내 제공
4. 이후 복구 재시도

#### UI 제안

- “백신/보안 소프트웨어가 파일 생성을 차단했을 수 있습니다.” 문구 제공
- 설치 폴더를 예외 경로로 추가하는 방법 안내

## 4. 추천 원클릭 복구 흐름

### 목표

사용자는 버튼 하나만 누르면 되고, 내부적으로는 아래 순서로 처리한다.

1. 현재 상태 진단
2. 문제 유형 분류
3. 부분 복구 또는 재설치 선택
4. 실패 시 `setup_mfa.bat --non-interactive` 폴백 실행
5. 최종 재진단
6. 성공/실패 및 다음 행동 안내

### 권장 알고리즘

#### 1) 사전 진단

- MFA 실행 파일 존재 여부 확인
- Python 실행 파일 존재 여부 확인
- pip 실행 파일 존재 여부 확인
- packaging stack import 검사
- 언어별 import 검사
- 모델 존재 여부 확인

#### 2) 1차 액션 결정

- MFA 없음 → 전체 설치
- Python 재구성 필요 → 전체 재설치
- packaging stack 손상 → 기존 환경 복구
- 언어 패키지 누락 → 기존 환경 복구
- 모델 누락 → 모델 다운로드

#### 3) 2차 폴백

1차 복구 실패 시:

- `setup_mfa.bat --non-interactive` 실행
- 완료 후 다시 진단

#### 4) 최종 결과 요약

사용자에게 최소한 아래 정보를 보여준다.

- 감지된 문제
- 시도한 복구 단계
- 최종 성공 여부
- 남은 수동 조치

## 6. 자동 복구 설계 시 유의점

### 1) 완전 자동 성공을 보장한다고 표현하지 않기

다음 문제는 앱 밖의 환경 요인이라 100% 제어하기 어렵다.

- 회사 네트워크/프록시
- TLS/인증서 문제
- 관리자 권한 정책
- VC++ 설치 정책
- 백신/EDR 격리
- 재부팅 필요 상태

따라서 UI 문구는 “자동 진단 및 복구를 시도합니다”가 적절하다.

### 2) 로그는 자세히, 사용자 메시지는 단순하게

사용자에게는 짧고 명확한 상태를 보여주고,
필요하면 복사 가능한 상세 로그를 함께 제공하는 구조가 좋다.

### 3) 무한 재시도는 피하기

권장 순서:

- 내부 복구 1회
- 배치 폴백 1회
- 최종 실패 안내

### 4) 최종 안내에는 항상 다음 행동을 포함하기

예:

- setup_mfa 배치 직접 실행 명령
- VC++ 런타임 설치 링크
- 네트워크/TLS 점검 안내
- 백신 예외 설정 안내

- 사용자용 FAQ 또는 도움말 초안
- QA에서 설치 실패 시나리오 테스트 케이스 정의
- 에러 메시지 및 상태 문구 표준화

향후 구현 시에는 이 문서의 문제 분류를 기준으로,
진단 결과(`issues`)와 실제 복구 액션을 1:1에 가깝게 연결하는 것을 권장한다.
