# 사용자 재학습/개인화 설계안

이 문서는 현재 `LightGBM` 기반 OTO ML 모델에 대해, 사용자가 자신의 데이터로 성능을 강화하거나 개인화된 번들을 만드는 방식을 정리한 설계안이다.

문서 상태:
- 설계안
- 미구현
- 현재 코드에 바로 포함된 사용자용 CLI/GUI는 없음

## 1. 전제

현재 런타임 ML은 `절대 파라미터를 처음부터 생성`하는 구조가 아니라, 기본 계산 결과를 입력으로 받아 `delta_offset`, `delta_cons`, `delta_cutoff`, `delta_pre`, `delta_ovl`를 예측하는 잔차 보정 구조다.

즉 사용자 개인화도 다음 원칙을 따른다.

- 기본 계산기는 유지한다.
- ML은 기본 계산을 보정한다.
- 개인화 모델은 기본 계산이 이미 어느 정도 맞는 포맷에서 특히 효과가 크다.

## 2. 용어 정리

이 문서에서 `파인튜닝`은 넓은 의미의 사용자 개인화를 뜻한다.

다만 `LightGBM` 특성상 권장 방식은 딥러닝식 `기존 체크포인트에 이어서 미세조정`이 아니라 아래 둘 중 하나다.

1. 기존 공용 데이터 + 사용자 데이터 병합 후 재학습
2. 기존 공용 데이터셋은 유지하고 사용자 데이터에 더 큰 가중치를 주어 재학습

권장 기본값은 `2번`이다.

## 3. 목표

- 사용자가 자신의 보이스뱅크 스타일에 맞춘 개인화 ML 번들을 만들 수 있게 한다.
- 언어/형식별 공용 모델과 사용자 모델을 분리해 관리한다.
- 공용 모델의 범용성을 완전히 잃지 않으면서, 사용자 데이터 쪽에 조금 더 맞게 한다.
- 특정 형식이 아직 공용 데이터가 부족해도, 사용자 로컬 환경에서는 실용적인 개선을 얻을 수 있게 한다.

## 4. 비목표

- 기본 계산기 제거
- ML 단독 절대 OTO 생성기화
- 단일 보이스뱅크만으로 범용 모델을 대체하는 것
- 런타임에서 온라인 학습 수행

## 5. 권장 개인화 모드

### 5.1 공용+사용자 재학습

가장 권장하는 모드다.

- 공용 데이터셋과 사용자 데이터셋을 함께 사용
- 사용자 데이터에 더 높은 sample weight 부여
- 결과는 `개인화 번들`로 export

장점:
- 범용성 유지
- 특정 화자/녹음 방식 적응 가능
- 과적합 위험이 상대적으로 낮음

### 5.2 사용자 전용 번들

특정 보이스뱅크 전용 보정기로 쓸 때만 허용하는 모드다.

- 사용자 데이터만으로 재학습
- 적용 범위는 해당 보이스뱅크나 같은 계열 음원으로 제한

장점:
- 스타일 적응이 강함

단점:
- 다른 보이스뱅크로 옮기면 성능이 급락할 수 있음
- 형식/녹음 스타일 편향이 커짐

기본 정책으로는 권장하지 않는다.

### 5.3 형식별 부트스트랩 번들

새 형식이나 데이터가 적은 형식을 위한 모드다.

- 같은 언어의 인접 형식 데이터를 일부 빌려 초기 번들을 만듦
- 이후 사용자 데이터가 쌓이면 해당 형식 전용 번들로 재학습

예:
- `CV`와 `연단음`
- `CVVC`와 `VCV`의 일부 bridge 계열

이 모드는 명시적으로 `bootstrap` 성격으로만 사용해야 한다.

## 6. 데이터 요구사항

사용자 개인화 학습에 필요한 최소 구성은 현재 공용 파이프라인과 같다.

- 수동 `oto.ini` 또는 신뢰 가능한 기준 OTO
- 자동 생성된 `oto.ini`
- 같은 음원에 대응하는 `TextGrid`
- 원본 `wav`
- 있으면 `custom phonemes`
- 있으면 `prefix.map`

중요:
- `prefix.map`이 있으면 alias의 접두/접미를 제거한 본체 alias 기준으로 학습해야 한다.
- 한국어 OTO에서 히라가나 alias는 제외한다.
- 인코딩이 혼재한 `oto.ini`는 fallback 읽기 후 정규화해야 한다.

## 7. 개인화 데이터 병합 정책

권장 병합 정책:

1. 공용 데이터셋을 그대로 유지
2. 사용자 데이터셋을 별도 수집
3. 두 데이터셋을 합친 뒤 `domain=base|user` 또는 유사 메타데이터 추가
4. 사용자 데이터에 더 높은 sample weight 부여

초기 권장 가중치:

- 공용 수동 라벨: `1.0`
- 사용자 수동 라벨: `1.5 ~ 3.0`
- pseudo_high: 공용/사용자 공통으로 감쇠
- pseudo_mid: 더 낮은 가중치
- pseudo_low: 제외

권장 시작값:

- 공용 manual: `1.0`
- 사용자 manual: `2.0`
- pseudo_high: `0.5 ~ 0.7`
- pseudo_mid: `0.2 ~ 0.4`

## 8. 학습 단위

개인화도 현재 구조를 유지하는 것이 안전하다.

- 언어별 분리
- 형식별 분리
- 필요하면 alias group별 추가 분기

즉 기본 단위는 다음과 같다.

- `japanese/cv`
- `japanese/vcv`
- `japanese/cvvc`
- `korean/cv`
- `korean/cvc`
- `korean/cvvc`
- `korean/vcv`

개인화 모델도 이 단위를 따르는 것을 기본으로 한다.

## 9. 평가 정책

개인화 모델은 반드시 두 방향으로 평가해야 한다.

1. 사용자 데이터에 대한 성능
2. 공용 holdout 데이터에 대한 성능

둘 중 하나만 좋아지는 모델은 기본 설치 모델로 쓰기 어렵다.

최소 평가 지표:

- target별 `baseline_mae`
- target별 `model_mae`
- alias type별 MAE
- `CV/-CV` 점프 비율
- suspicious ratio
- P90 오차

권장 추가 지표:

- 보이스뱅크별 편차
- 형식별 편차
- ML 적용 후 validator 경고 변화량

## 10. 권장 배포 방식

개인화 결과는 공용 번들을 덮어쓰지 않고 별도 번들로 취급한다.

예시 구조:

- `models_installed/oto_ml_user/japanese/cv/...`
- `models_installed/oto_ml_user/korean/cvc/...`

런타임 선택 우선순위 권장:

1. 사용자 설치 번들
2. 프로젝트 내 설치 번들
3. 기본 자산 번들
4. 번들 없음 -> 기본 계산만 사용

이렇게 해야 사용자가 공용 번들을 망가뜨리지 않고 롤백할 수 있다.

## 11. 메타데이터 권장 항목

개인화 번들의 `model_meta.json`에는 최소한 아래 정보가 있어야 한다.

- `language`
- `format_type`
- `base_model_version`
- `training_mode`
  - `base_plus_user`
  - `user_only`
  - `bootstrap`
- `base_rows`
- `user_rows`
- `voicebank_count`
- `user_weight`
- `filters`
- `created_at`

민감 정보 보호를 위해:

- 절대 경로는 저장하지 않는다.
- 실제 사용자 보이스뱅크 폴더명은 익명 ID로 치환 가능하게 한다.

## 12. 구현 권장 순서

사용자용 스크립트를 나중에 만든다면 순서는 다음이 적절하다.

1. 공용 데이터 수집 파이프라인 안정화
2. 사용자 데이터만 별도 수집하는 CLI 추가
3. 공용+사용자 병합 CSV 생성기 추가
4. 사용자 가중치 옵션 추가
5. 개인화 번들 export/install 분리
6. 공용/사용자 성능 비교 리포트 추가

## 13. 권장 CLI 형태

아래는 설계 예시이며, 현재 구현된 인터페이스는 아니다.

```powershell
python ml/scripts/collect_oto_ml_training_data.py `
  --config ml/configs/training_data_roots.yaml `
  --out workspace/base_dataset.csv

python ml/scripts/collect_oto_ml_training_data.py `
  --config ml/configs/user_training_roots.yaml `
  --out workspace/user_dataset.csv

python ml/scripts/train_oto_ml_model.py `
  --lang korean `
  --format cvc `
  --dataset workspace/merged_dataset.csv `
  --out-dir workspace/models/korean/cvc/user_v1
```

개인화 전용으로는 이후 다음 성격의 옵션을 추가하는 것이 적절하다.

- `--user-dataset`
- `--user-weight`
- `--training-mode base_plus_user|user_only|bootstrap`
- `--export-user-bundle`

## 14. 리스크

### 14.1 단일 보이스뱅크 과적합

가장 흔한 문제다.

- 특정 화자의 습관
- 특정 녹음실 잡음
- 특정 alias 스타일
- 특정 pitch affix 규칙

이것만 학습하면 다른 음원에서 오히려 악화된다.

### 14.2 기준 OTO 품질 문제

수동 OTO가 완전히 정답이 아니면, ML은 그 오차까지 학습한다.

따라서 개인화 데이터는 양보다 품질이 더 중요하다.

### 14.3 정렬 오류 전염

TextGrid가 잘못되면, 개인화 모델이 그 패턴을 강화할 수 있다.

따라서 저신뢰 정렬 샘플은 가중치를 낮추거나 제외해야 한다.

## 15. 최종 권장안

현재 프로젝트에 가장 맞는 사용자 개인화 방향은 다음이다.

1. `LightGBM`은 계속 잔차 보정 모델로 유지
2. 사용자 개인화는 `공용+사용자 재학습`을 기본으로 함
3. 사용자 데이터는 높은 가중치만 주고, 공용 데이터는 유지
4. 결과는 공용 모델을 덮지 않는 `개인화 번들`로 배포
5. 평가 리포트는 공용/사용자 두 축을 모두 제공

핵심은 `개인화는 가능하지만, 범용 모델 대체가 아니라 안전한 편향 추가`로 다뤄야 한다는 점이다.
