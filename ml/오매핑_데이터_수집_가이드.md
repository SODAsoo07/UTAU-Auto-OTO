# 오매핑 데이터 수집 가이드

## 목적

이 문서는 `CVVC`, `CVC`를 중심으로 자동 `oto.ini`의 오매핑 사례를 수집하고, 이후 `OTO ML` 재학습에 넣기 위한 실무 규칙을 정리한다.

여기서 말하는 오매핑은 아래를 뜻한다.

- 파라미터 값 자체보다, `CV`, `-CV`, `VC`, `VV`가 **다른 음절 / 다른 mora / 다른 연결 위치**를 가리키는 경우
- 예: 일본어 `CVVC`에서 `か`가 실제로는 다음 mora를 가리키는 경우
- 예: 한국어 `CVC/CVVC`에서 `CV`와 `VC`가 서로 다른 발음을 기준으로 분리되는 경우

## 결론

- 가장 좋은 수집 방식은 **자동 생성한 `oto.ini`와, 그 파일을 기준으로 사람이 수정한 `oto.ini`를 한 쌍으로 보관하는 것**이다.
- **기존 학습 데이터셋에 이미 들어 있던 데이터만 써야 하는 것은 아니다.**
- 오히려 **학습셋에 없던 새 보이스뱅크 / 새 녹음본의 오매핑 수정 사례**도 충분히 가치가 있다.
- 단, **언어 / 형식 / 보이스뱅크는 분리해서 관리**해야 한다.

## 최소 필요 구성

한 보이스뱅크 단위로 최소 아래가 필요하다.

- 원본 `wav`
- 같은 `wav` 기준의 `TextGrid`
- 자동 생성된 `oto.ini` 또는 `oto_auto_ml.ini`
- 사람이 수정한 `oto_manual.ini`

권장 추가 파일:

- `prefix.map`
- `character.txt`
- 사용한 설정 메모

## 권장 폴더 구조

권장 구조 예시는 아래와 같다.

```text
Voice_Datas/
  Kr/
    CVC/
      Bank_A/
        wav...
        TextGrid...
        oto_auto_ml.ini
        oto_manual.ini
        prefix.map
    CVVC/
      Bank_B/
        ...
  Jp/
    CVVC/
      Bank_C/
        ...
```

핵심은 아래 3개다.

- 언어별 분리
- 형식별 분리
- 보이스뱅크별 분리

## 어떤 데이터를 모아야 하나

### 가장 가치가 큰 사례

- 일본어 `CVVC`
  - `CV`, `-CV`가 한 mora 앞으로 밀린 사례
  - 요음, 삽입 모음, 장음에서 잘못 고른 사례
- 한국어 `CVC`
  - `CV`와 종성성 `VC`가 서로 다른 기준점에 걸린 사례
  - `VC -> 다음 CV` 연결이 삐걱거리는 사례
- 한국어 `CVVC`
  - `CV`가 다른 음절로 밀린 사례
  - `VC`가 다음 음절 onset과 잘못 붙은 사례

### 우선순위가 낮은 사례

- 단순히 3~5ms 정도만 미세 조정한 사례
- alias 설계 자체를 크게 갈아엎은 사례
- 같은 발음이 아니라 전혀 다른 alias 체계를 새로 만든 사례

## 자동본과 수동본 작성 규칙

### 가장 좋은 방식

- 자동 생성본을 복사한다.
- **같은 alias 줄을 유지한 상태로** 수동 수정한다.
- `offset`, `cons`, `cutoff`, `pre`, `ovl`만 고친다.

즉 아래 조건이 가장 좋다.

- alias inventory 유지
- 줄 순서(line order) 가능하면 유지
- 같은 `wav`, 같은 `TextGrid` 유지

### 가능하지만 품질이 떨어지는 방식

- alias 추가/삭제가 큰 경우
- 줄 순서를 크게 재배치한 경우
- 다른 `wav` / 다른 정렬 결과를 섞은 경우

이 경우도 완전히 못 쓰는 건 아니지만, 현재 파이프라인에서는 학습 row 매칭 안정성이 떨어진다.

## 꼭 기존 학습 데이터셋에 있던 데이터여야 하나

아니다.

새 데이터도 충분히 사용할 수 있다. 오히려 아래 이유로 더 좋을 수 있다.

- 기존 데이터에 없던 보이스뱅크 특성을 추가할 수 있음
- 과적합을 줄이고 일반화를 높일 수 있음
- 실제 실사용에서 발견된 오매핑을 바로 반영할 수 있음

다만 조건이 있다.

### 새 데이터를 바로 넣어도 되는 조건

- 현재 지원 언어/형식 안에 들어감
  - 한국어: `CV`, `CVC`, `CVVC`, `VCV`
  - 일본어: `CV`, `CVVC`, `VCV`
- 자동본과 수동본이 같은 `wav` 묶음을 기준으로 함
- `TextGrid`가 있음

### 바로 넣기 어려운 경우

- `TextGrid`가 없음
- alias 설계가 현재 지원 형식과 많이 다름
- 자동본과 수동본이 서로 다른 녹음 세트를 기준으로 만들어짐

즉, **기존 학습 데이터셋에 포함되어 있었는지 여부보다, 같은 기준의 auto/manual pair를 만들 수 있는지가 더 중요하다.**

## alias별로 분리해야 하나

물리적으로 alias별 폴더를 따로 만들 필요는 없다.

대신 아래처럼 나중에 학습 시 필터링하는 것이 맞다.

- `CV` 계열만 학습
- `bridge` 계열만 학습
- `mono`만 학습

현재 기준 alias family는 아래처럼 보면 된다.

- `cv`
  - `cv`, `cv_head`
- `vowel`
  - `mono`
- `bridge`
  - `vc`, `vv`, `vcv`

## 실제 수집 절차

### 1. 자동 oto 생성

- 대상 보이스뱅크에 대해 자동 `oto.ini`를 생성한다.
- 가능하면 `ML off`, `ML on` 둘 다 비교해 보고 더 문제가 잘 드러나는 쪽을 기준으로 저장한다.

권장 파일명:

- `oto_auto_ml.ini`
- 또는 `oto_auto_baseline.ini`

### 2. 수동 수정

- 자동본을 복사해 `oto_manual.ini`를 만든다.
- 실제로 잘못 들리는 줄만 우선 수정한다.
- 특히 아래를 우선 본다.
  - `CV`
  - `-CV`
  - `VC`
  - `VV`

### 3. 수정 규칙 점검

수정본에 대해 아래를 확인한다.

- alias는 자동본과 동일한가
- 같은 `wav`를 기준으로 수정했는가
- `TextGrid`와 모순되는 수준의 극단적 수정이 아닌가
- 실제로 오매핑을 바로잡은 것인가, 단순 취향 보정인가

### 4. 학습 데이터 폴더로 편입

- 해당 보이스뱅크 폴더에 `oto_manual.ini`를 같이 둔다.
- 언어/형식 루트 아래 올바른 위치에 정리한다.

### 5. stage / collect 재실행

- `stage_training_sources.py`
- `prepare_staged_auto_pairs.py`
- `collect_oto_ml_training_data.py`

이 순서로 다시 수집한다.

## 좋은 사례 / 나쁜 사례

### 좋은 사례

- 자동본에서는 `CV`가 다음 음절을 가리킴
- 수동본에서 같은 alias 줄의 파라미터만 고쳐 올바른 음절 위치로 맞춤

### 나쁜 사례

- 자동본에는 없는 alias를 다수 추가
- 자동본과 수동본의 줄 순서를 완전히 새로 재작성
- 같은 보이스뱅크라도 다른 pitch 폴더의 `oto`를 섞어 둠

## 품질을 높이는 수집 규칙

### 권장

- 한 보이스뱅크 전체를 조금씩 수정하는 것보다
  - **실제로 틀린 줄만 정확히 수정한 사례**를 모으는 것이 더 가치가 크다.
- `CVVC/CVC`는 다음을 우선 수집한다.
  - `CV/-CV` 오매핑
  - `VC -> 다음 CV` 연결 어긋남
  - 요음/삽입 모음/장음 오해석

### 비권장

- 전체를 완벽하게 다듬으려다 일관성이 깨지는 수정
- 사람이 임의로 alias 체계를 재설계한 파일

## 현재 프로젝트 기준 권장 운용

- `delta` 학습은 전 형식에서 계속 사용 가능
- `selector`는 형식별로 신중히 쓴다
- 특히 `CVVC/CVC`는 **오매핑 사례 수집 -> 계산식 개선 -> selector 재평가** 순서가 맞다

즉, 오매핑 데이터는 단순 양보다 아래가 중요하다.

- 같은 기준의 auto/manual pair
- 실제 오매핑을 바로잡은 사례
- 언어/형식/보이스뱅크 구분

## 체크리스트

- [ ] `wav`가 있다
- [ ] `TextGrid`가 있다
- [ ] 자동 `oto.ini`가 있다
- [ ] 수동 수정 `oto_manual.ini`가 있다
- [ ] alias inventory를 크게 바꾸지 않았다
- [ ] 실제 오매핑 줄을 우선 수정했다
- [ ] 언어/형식/보이스뱅크 위치가 올바르다

## 한 줄 요약

- **자동본 + 수동 수정본 한 쌍이면 된다.**
- **기존 학습셋에 있던 데이터만 쓸 필요는 없다.**
- **새 데이터도 현재 지원 언어/형식 안에서 auto/manual pair와 TextGrid만 맞으면 충분히 학습에 넣을 수 있다.**
- 취향 차이 말고, 웬만하면 정말 오류인 것만 수정할 것
