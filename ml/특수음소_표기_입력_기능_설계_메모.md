# 특수음소 표기 입력 기능 설계 메모

## 목적

일본어/한국어 음원 중에는 파일명에 일반적인 음절 표기 외에 별도의 특수음소 표기가 섞이는 경우가 있다.

예:
- `3`
- `l`
- `x`
- `sh`
- 보이스뱅크 제작자가 따로 정의한 축약 표기

이 경우 현재 기본 파일명 파서만으로는 음절 수를 안정적으로 복원하기 어렵다.  
향후에는 사용자가 직접 특수 표기 규칙을 입력해 `Lab` 생성, 사전 생성, 정렬에 반영할 수 있어야 한다.

## 현재 문제

현재는 다음 두 경우가 섞여 있다.

1. 언어 선택이 잘못되어 다른 파서를 탄 경우
2. 언어는 맞지만, 파일명에 프로젝트별 특수 표기가 들어 있어 기본 파서만으로는 해석이 부족한 경우

1번은 UI 개선으로 완화할 수 있지만, 2번은 별도 입력 기능이 필요하다.

## 목표 기능

사용자가 보이스뱅크별 특수 표기 규칙을 직접 입력하고 저장할 수 있어야 한다.

적용 대상:
- `Lab` 생성
- MFA 사전 생성
- 파일명 기반 음절 추정
- 필요하면 추후 alias 정규화에도 재사용

## 권장 입력 방식

1. 텍스트 규칙 파일
- 가장 먼저 구현하기 쉬운 형태
- 예:
```txt
3=ra
l=ra
x=ra
sh=sh
ti=てぃ
tu=とぅ
```

2. UI 전용 입력란 + 파일 저장
- 고급 옵션 탭 또는 언어별 고급 설정 탭에 배치
- 사용자가 편집 후 `.txt`로 저장

3. 언어별/보이스뱅크별 presets
- 자주 쓰는 패턴은 나중에 프리셋으로 추가 가능

## 데이터 구조 제안

형식은 단순 key-value가 맞다.

예:
```json
{
  "language": "japanese",
  "rules": {
    "3": "ra",
    "l": "ra",
    "x": "ra",
    "sh": "sh"
  }
}
```

또는 현재 커스텀 phoneme mapping과 맞추기 위해 단순 텍스트도 가능하다.

핵심은:
- 한 토큰을 어떤 음절/음소 시퀀스로 치환할지
- 언어별로 다르게 적용할지
- 보이스뱅크별 파일로 분리할지

## 적용 우선순위

1. `Lab` 생성기
- 가장 먼저 필요
- 파일명 파싱 실패를 줄이는 데 직접적

2. 사전 생성기
- `Lab` 내용과 같은 규칙을 써야 일관성이 맞음

3. alias 정규화/ML feature 추출
- 나중 단계
- 초기 구현에서는 필수 아님

## UI 설계 제안

표시는 눈에 띄되 기본 사용자 흐름을 방해하지 않는 위치가 맞다.

추천 위치:
- 고급 옵션 영역
- 언어 선택 아래 또는 `Lab 생성` 단계 설명 옆

추천 구성:
- `특수음소 표기 규칙 파일`
- 파일 선택 버튼
- 간단한 도움말 버튼
- 현재 적용 중인 규칙 수 표시

## 도움말에 들어갈 내용

사용자에게는 아래 정도만 보여주면 충분하다.

- 파일명에 특수 표기가 있으면 이 규칙 파일로 해석할 수 있습니다.
- 예: `3=ra`, `sh=sh`
- 규칙을 지정하지 않으면 기본 파서만 사용합니다.

## 구현 시 주의점

1. 전체 경로가 아니라 토큰 단위로 적용할 것
- 문자열 부분일치로 오인식하면 안 됨

2. 언어별 parser보다 먼저 무작정 치환하지 말 것
- 파일명 토큰화 이후, 토큰 단위 규칙 적용이 더 안전함

3. 기본 파서를 완전히 대체하지 말 것
- 규칙이 없는 토큰은 기존 파서가 처리해야 함

4. 로그를 남길 것
- 어떤 파일에서 어떤 특수 규칙이 적용됐는지 로그에 보여줘야 디버깅 가능

## 권장 구현 순서

1. 규칙 파일 로더
2. 일본어 `Lab` 생성기 토큰 치환
3. 한국어 `Lab` 생성기 토큰 치환
4. 사전 생성기 공통 적용
5. UI 파일 선택 입력 추가
6. 로그/검증 메시지 추가

## 현재 판단

이 기능은 유효하고 실사용 가치가 높다.  
다만 지금 즉시 막는 문제의 1차 원인은 아니므로, 우선순위는:

1. 언어 선택 실수 방지 UI
2. 기존 파서 안정화
3. 그 다음 특수음소 표기 입력 기능

으로 두는 것이 맞다.
