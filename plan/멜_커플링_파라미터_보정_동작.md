# 멜 커플링 모델 파라미터 보정 동작

## 1. 기본 원리
- 이 모델은 OTO 값을 처음부터 새로 생성하지 않는다.
- 먼저 `oto_auto_ml.ini` 또는 base OTO의 값을 기준점으로 잡는다.
- 그 다음 row별 feature와 멜 기반 경계 신호를 보고 `얼마나 이동시킬지(delta)`를 예측한다.

현재 예측 타깃은 아래 5개다.
- `delta_offset`
- `delta_cons`
- `delta_cutoff`
- `delta_pre`
- `delta_ovl`

즉 최종값은 아래처럼 계산된다.
- `final_offset = base_offset + delta_offset`
- `final_cons = base_cons + delta_cons`
- `final_cutoff_abs = base_cutoff_abs + delta_cutoff`
- `final_pre = base_pre + delta_pre`
- `final_ovl = base_ovl + delta_ovl`

## 3. 각 파라미터에 주는 영향

### 3.1 `offset`
- 역할:
  - 샘플 재생 시작점을 정한다.
  - 너무 앞이면 숨/무음이 섞이고, 너무 뒤면 onset이 잘린다.
- 모델이 보는 핵심 단서:
  - `mel_offset_candidate_ms`
  - onset patch 에너지/voiced 비율
  - blank/silence confidence
  - 같은 파일 내 VC/CV 상대 위치
- 학습에서 받는 제약:
  - `offset >= 0`
  - `offset`이 멜 onset 후보와 너무 멀어지면 alignment loss가 증가
- 실전적 효과:
  - onset 직전 무음 제거
  - 자음 시작을 지나치게 늦추는 오차 억제
  - CV/VCV에서 점프성 오매핑 감소

### 3.2 `preutter`
- 역할:
  - 노트와 음성 onset이 실제로 맞물리는 기준점이다.
  - 리듬과 타이밍 체감에 직접 영향 준다.
- 모델이 보는 핵심 단서:
  - offset과 consonant 사이 구조
  - 모음핵 시작 보조 타깃
  - onset patch feature
- 학습에서 받는 제약:
  - `ovl <= pre`
  - `pre + margin <= consonant`
- 실전적 효과:
  - note hit가 앞당겨지거나 늦어지는 문제 완화
  - onset은 살리고 리듬은 안정적으로 유지

### 3.3 `overlap`
- 역할:
  - 이전 음과 현재 음의 교차 구간을 정한다.
  - 연결감과 발음 뭉개짐 사이 균형에 영향 준다.
- 모델이 보는 핵심 단서:
  - `preutter`와의 상대 위치
  - alias type
  - CV/VC/VCV 관계
- 학습에서 받는 제약:
  - `overlap <= preutter`
- 실전적 효과:
  - overlap이 과도하게 커져 onset을 먹는 문제 억제
  - 연결은 유지하되 자음이 뭉개지는 현상 완화

### 3.4 `consonant`
- 역할:
  - 자음 구간의 길이 또는 자음 유지 경계를 나타낸다.
  - 발음 선명도에 직접 영향 준다.
- 모델이 보는 핵심 단서:
  - onset 이후 voiced/unvoiced 구성
  - alias type
  - 모음핵 시작 보조 타깃
- 학습에서 받는 제약:
  - `preutter + margin <= consonant`
  - `consonant + margin <= cutoff_abs`
- 실전적 효과:
  - 자음이 너무 짧아져 뭉개지거나
  - 너무 길어져 모음을 잠식하는 문제를 줄인다

### 3.5 `cutoff`
- 역할:
  - 샘플 tail을 어디서 자를지 정한다.
  - 다음 음으로 넘어갈 때 잔향/숨/잡음이 남는지에 영향 준다.
- 모델이 보는 핵심 단서:
  - `mel_cutoff_candidate_ms`
  - tail patch 에너지
  - tail silence 비율
  - blank confidence
  - 다음 onset 보조 타깃
- 학습에서 받는 제약:
  - `consonant + margin <= cutoff_abs`
  - `cutoff_abs`가 멜 tail 후보와 너무 멀어지면 alignment loss가 증가
- 실전적 효과:
  - tail 잡음 과다 유지 억제
  - 다음 음 onset을 침범하는 cutoff 오차 완화

## 4. confidence가 하는 일
- 모델은 delta 5개와 별도로 confidence도 예측한다.
- confidence는 `이 보정값을 얼마나 믿을 수 있는가`에 대한 점수다.
- 런타임에서는 이 점수가 낮으면 coupled 결과를 그대로 쓰지 않고 fallback 또는 보수적 적용으로 내려갈 수 있다.

## 5. 보조 헤드가 timing에 주는 영향
- 현재 보조 타깃:
  - `aux_vowel_start_rel`
  - `aux_vowel_end_rel`
  - `aux_next_onset_rel`
- 이 값들은 최종 OTO 값으로 직접 저장되지는 않는다.
- 대신 학습 중에 `offset`, `preutter`, `consonant`, `cutoff`가 어느 위치를 중심으로 움직여야 안정적인지 구조적 기준을 제공한다.

실전적으로는:
- 모음핵 시작 예측이 안정되면 `preutter`와 `consonant`가 덜 흔들린다.
- 다음 onset 예측이 안정되면 `cutoff`가 다음 음을 침범하는 일이 줄어든다.

## 6. VC-CV 페어링 제약이 주는 영향
- 같은 `wav_norm` 안에서 가까운 `VC <-> CV/CV_head`를 양방향으로 묶는다.
- 모델은 각 row를 독립적으로만 맞추는 것이 아니라, pair 사이 gap도 manual 데이터와 비슷하게 유지하도록 학습된다.

실전적 효과:
- `VC`만 앞으로 밀리고 `CV`는 뒤로 남는 식의 내부 구조 붕괴 완화
- 같은 녹음 안에서 상대 위치 일관성 유지

## 7. 학습 단위
- 현재 학습은 기본적으로 `언어 + 형식` 단위의 단일 모델이다.
- 예를 들어 한국어 `cvvc`면 여러 보이스뱅크와 여러 서브뱅크의 row를 모두 같은 CSV에 모아 하나의 `cvvc` 모델로 학습한다.
- 다만 holdout은 기본적으로 `wav_norm` 기준이라 같은 녹음 파일의 row가 train/valid로 섞이지 않게 한다.

즉 의미는 아래와 같다.
- 형식 공통 규칙은 최대한 공유해서 학습한다.
- 파일 내부 관계는 holdout과 pair loss로 보호한다.
- 보이스뱅크 스타일 차이는 feature와 confidence가 흡수한다.

## 8. 해석 시 주의
- 이 모델은 absolute OTO generator가 아니라 `base OTO refiner`다.
- 따라서 base OTO가 너무 망가진 bank에서는 delta만으로 회복 가능한 범위에 한계가 있다.
- 반대로 base OTO가 대체로 맞는 bank에서는 row별 세밀 보정에 강하다.
- `matched_rows`가 거의 없거나 `skip_mapping_far`가 과도한 bank는 모델 성능보다 데이터 생성 단계 문제일 가능성이 높다.
