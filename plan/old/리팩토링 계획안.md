# 리팩토링 계획안

## 목적
- 기능 모듈화로 수정 효율 상승
- 테스트 효율화(핵심: mel 커플링 모델)
- AI 에이전트가 코드의 기능을 더 쉽게 편집할 수 있도록 구조 개선
- 미사용 레거시 스크립트 폐기

## 범위
- 핵심 ML(멜 커플링 모델) 관련 코드 및 스크립트 중심
- core/oto_ml_* 및 ml/scripts 파이프라인 일체
- 테스트는 mel 커플링 관련 테스트에 집중(선택적 실행/속도 개선)
- 폴더 구조 재편 포함

## 리팩토링 원칙
- 기능 단위 모듈 분리, 명확한 책임 경계
- 공용 로직은 core 하위의 공통 모듈로 정리
- 학습/평가/추론 스크립트는 “얇은 래퍼”로 유지
- 외부 인터페이스(모델 파일/메타 포맷/CLI)는 가능하면 유지
- 변경 영향이 큰 항목은 별도 마이그레이션 가이드 문서화

## 대상 구조(초안)
- core/
  - oto_ml/
    - coupled/
      - model.py (torch 모델 구조)
      - training.py (학습 루프/손실 구성)
      - inference.py (예측 및 후처리)
    - features/
      - feature_extraction.py (feature row 생성)
      - schema.py (FEATURE_NAMES/AUX_TARGET_NAMES 등)
      - caches.py (캐시 경로/버전)
    - pairing/
      - vc_cv_pairing.py (페어링 로직, 손실 계산)
    - utils/
      - io.py, math.py, typing.py
- ml/scripts/
  - coupled/
    - build_dataset.py
    - train.py
    - evaluate.py
    - export.py
    - install.py

## 단계별 계획
1. 현황 파악
   - mel 커플링 관련 모듈/스크립트 의존 그래프 정리
   - 호출 빈도 낮거나 중복되는 스크립트 목록화
   - 테스트 중 멜 커플링 관련만 선별
2. 모듈 분리
   - 모델/학습/추론/피처/페어링을 파일 단위로 분리
   - 공통 util 이동(중복 함수 제거)
3. 폴더 구조 재편
   - core/oto_ml_* 분산 파일을 core/oto_ml/ 하위로 통합
   - ml/scripts 재배치 및 스크립트 이름 통일
4. 테스트 효율화
   - mel 커플링 테스트 묶음만 단독 실행 가능하게 구성
   - 느린 테스트는 마커/스킵 조건 분리
5. 레거시 스크립트 폐기
   - 실제 미사용 + 모듈화 후 호출되지 않는 스크립트 제거
   - 대체 경로(새 스크립트) 명시
6. 문서화/마이그레이션
   - 변경된 경로/사용법 정리
   - 개발현황_Mel 업데이트

## 레거시 판정 기준
- 현재 파이프라인에서 호출되지 않음
- 모듈화 후 대체 스크립트가 존재함
- 최근 변경/사용 기록이 없고 기능 중복됨

## 테스트 효율화 기준
- mel 커플링 기능 테스트만 기본 실행
- 기타 테스트는 선택 실행 플래그 제공

## AI 에이전트 편집성 개선 포인트
- 파일명/모듈명이 기능 단위로 직관적으로 매핑
- 단일 책임(모델/학습/데이터/평가 분리)
- 변경 지점이 명확하도록 API 경계 정리
- 각 모듈 상단에 간단한 역할 설명 추가

## 산출물
- 새 폴더 구조 반영된 코드
- 레거시 제거 목록 및 삭제 결과
- mel 커플링 테스트 전용 실행 경로
- 마이그레이션/운영 가이드 문서
