# TextGrid 약화 실행 계획 (KR+JA, 매핑+타이밍)

## Summary
- MFA TextGrid는 "순서/대략 경계"만 유지하고, 저신뢰 구간에서는 멜 기반 플랜과 앵커 락 완화(lite)로 타이밍을 보정한다.
- 매핑 신뢰도는 TextGrid 신뢰도에 의존하되, blank/멜 신뢰도에 따라 cap을 더 낮춰 TextGrid 영향력을 줄인다.
- KR/JA 공통 정책으로 적용하고, 필요 시 언어별 분리 가능한 구조로 유지한다.

## Key Changes
1) Alignment Weight 산출(파일 단위)
- alignment_weight = clamp01(textgrid_trust_score * 0.85 - max(0, blank_conf_mean - 0.45) * 0.35)
- blank_conf_mean이 없으면 alignment_weight = textgrid_trust_score * 0.85
- 이 값은 매핑 정책/앵커 락에 공통 사용

2) 매핑 정책 약화(순서 고정 강화)
- resolve_plan_policy / resolve_runtime_mapping_policy의 trust 입력을 alignment_weight로 교체
- alignment_weight < 0.55일 때 prefer_filename_sequence 강제(파일명 타깃 존재 시)
- CVVC/VCV/CV/CVC 멜 플랜 사용 기준 완화
  - blank_conf_mean 기준 0.55 -> 0.45
  - alignment_weight < 0.65이면 mel plan 허용(기존 env 토글 유지)

3) 타이밍 약화(앵커 락 lite)
- 앵커 락 적용 시 lite=True 조건
  - alignment_weight < 0.58 또는 blank_conf_mean >= 0.55
- TextGrid 경계의 강제 이동을 줄여 멜 기반 타이밍/ML 보정 여지를 확보

4) 로깅/진단
- 매핑 로그/trace에 alignment_weight, blank_conf_mean, anchor_lock_lite 포함
- 디버깅 시 TextGrid 약화 동작 근거를 추적 가능하도록 메시지 추가

## Implementation Notes
- KR/JA generator에서 alignment_weight, blank_conf_mean 산출 및 전달
- 매핑 정책 함수는 trust 입력을 alignment_weight로 대체
- 앵커 락 호출부에서 lite 플래그 조건 추가
- 주요 수정 대상
  - core\oto_generator.py
  - core\ja_oto_generator.py
  - core\oto_runtime_policy.py

## Test Plan
1) KR/JA 샘플 파일 3~5개로 auto-oto 실행
2) 로그에서 alignment_weight, anchor_lock_lite 활성화 여부 확인
3) oto.ini에서 offset/pre가 맨 앞 공백으로 쏠리는 현상 감소 여부 확인
4) 기존 정상 파일에 대해 리듬/자음 타이밍 과변형 여부 비교

## Assumptions
- TextGrid는 순서/대략 경계만 제공하며, 세부 타이밍은 멜 신뢰도 중심으로 보정한다.
- KR/JA 공통 정책으로 적용하되, 필요 시 언어별 env 분리 가능하다.
